# 整场景生成与画外旁白叙事

已跑通的示例：[《垃圾車來了！》160 秒旁白字幕影片](https://ishare.js.gripe/s/f410eb1ff6d3493ea7280c99623472f4)。76 张生成姿态、11 段台湾中文画外旁白、43 条旁白字幕、原创音效与轻柔配乐，以 24fps 编码。源图为 836×470／1672×941，1080p 是放大输出。

这是叙事制作流程成熟度的示例，人物连续动画仍有明显停格。字幕按画外旁白分句，不要求人物对嘴型；字幕时间在实际语音片段内按句长分配，未声称逐字强制对齐。

## 从故事到交付

1. 锁定人物、物品所有权、故事动线和时间窗。
2. 将前一整张影格与完整场景／人物参考上传给 ImageGen，描述下一动作。人物、背景、光线与接触影子一起生成，允许合理的背景视角变化。
3. 检查脚底支撑、行走方向、持物、接触顺序、数量及遮挡。失败图隔离在 `failures`，不留在正式 `assets/frames`。
4. 将筛选影格组织为明确时段；只有原图停留与切接，不进行骨骼变形、人物偏移或光流补帧。
5. 在独立时间窗合成画外旁白，测量实际时长；让物件操作的叙述跟随画面事件，不要求嘴型同步。
6. 混入轻柔配乐与环境音效，旁白期间降低背景音，加上旁白字幕，再编码、完整解码、核对来源与音量。

```sh
python video/scene/render.py
python video/scene/verify.py
```

媒体已经迁出仓库。重建前运行 python tools/media.py fetch --prefix video/scene/assets/frames/ 取回并验证原图，再按下方命令重新合成旁白。图片下载不调用生成模型，语音重建会访问在线服务，不能保证与历史音档逐字节相同。输出在忽略的 `output` 中。项目时段、图片哈希及原生尺寸见 [project.json](project.json)，旁白内容见 [narration_plan.json](narration_plan.json)。

## 重新合成旁白

使用用户选定的 [wangwangit/tts](https://github.com/wangwangit/tts) Microsoft REST 语音路径，本地执行。初版 Edge WebSocket 曾回 403，因此这里保留实际成功的路径，不依赖第三方演示站是否在线。

```sh
python video/scene/bootstrap_tts.py
node video/scene/scripts/synthesize_narration.mjs
python video/scene/render.py
```

工具源码已纳入根目录 third_party/tts，保留上游固定版本、原始 MIT 许可证与文件哈希；bootstrap 只核验源码，不再克隆仓库。历史音档不再提交，重新合成会更新本地旁白清单。台湾声线 `zh-TW-HsiaoChenNeural` 作为画外叙述者；不替两个画中人物假做同步对白。

使用 `--check-cache` 可以只检查哪些片段需要重做，不发起合成请求。缓存匹配文本、声线、语速、音高、风格、音量和音档哈希；修改旁白后不能仅凭同名文件复用旧音讯。渲染时从实际旁白的文本、时长和时间窗重新生成分句字幕。

## 能力边界

提示词明确 limit：同一小动作段最多一个接触事件，人物完整处于可行走区域；脚底与承重平面清楚。人物与栏杆、密集前景、其他人的肢体保持明确分离，不生成复杂的前后遮挡链。需要接触时优先鞋底或手部近景，保留物件接触、握住、离开、放下、释放的顺序。无法辨认的遮挡直接标记、隔离，换视角继续叙事。

门前平台、小水窪落脚、撿瓶及分流交付能形成可检查的主要状态。复杂护栏遮挡、密集步态与物件计数仍可能失败。见 [失败分类](failures/README.md)。避开遮挡构图是叙事处理方案，不能当成模型的遮挡能力已修复。
